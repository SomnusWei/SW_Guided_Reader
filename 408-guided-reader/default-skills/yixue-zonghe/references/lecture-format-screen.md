# 讲义「屏幕连续版」规范（平板笔记 App · 无界笔记形态）

> 适用范围：讲义除默认的 OneNote 原生 HTML 之外，**额外**要一份能导入**平板笔记 App**
> （华为笔记 / StarNote 鸿蒙版等）**无界笔记**里**手写批注**的连续版形态。
> 触发语示例：「要在平板上批注」「导入华为笔记/StarNote」「不要 PDF 那种按页切的感觉」「左边目录右边内容」。

---

## 一、为什么必须另出一版（先读，别绕开）

| 事实 | 依据 |
|---|---|
| **HTML 无法导入**任何一款平板笔记 App | 华为笔记只支持 图片 / PDF / DOC·PPT / hinote；StarNote 支持 PDF/EPUB/DOC/TXT/CAJ/图片 |
| **PDF 一定有「页」**，与用户要的「不要页面尺寸的切割感」直接冲突 | PDF 是分页格式，A4 一页 ≈ 1050px，一份讲义要 50+ 页 |
| **图片**是唯一能进「无界画布」又被两端同时支持的载体 | 两个 App 都能把图片插入无界笔记并直接在其上手写 |
| 没有任何单一格式能同时给到「无界画布」＋「原生目录大纲」 | 故目录**烘进版面**（左栏），不依赖 App 能力 |

**结论**：以**超长 PNG**为主产物（无界笔记里手写批注），**长页 PDF**为附件（文字可搜索、可打印）。
两者分片一一对应，便于对照。

---

## 二、交付形态

| 产物 | 命名 | 用途 |
|---|---|---|
| 屏幕版 HTML | `<讲义名>_屏幕版.html` | 版式源文件；也可直接在浏览器里看、打印 |
| 超长图（主产物） | `<同名目录>/图/NN_<高度>px.png` | 导入平板笔记 App 的无界笔记，在其上手写批注 |
| 长页 PDF（附件） | `<讲义名>_屏幕版.pdf` | 一片一页、**一片对一图**；文字可搜索、可打印 |

**产物目录**：默认 `<讲义源文件所在目录>/<讲义名>_屏幕版/`（弹幕式，不进 Git）。

---

## 三、版式规范（照抄，不得自创）

| 项 | 规定 |
|---|---|
| 画布总宽 | **1600px**（≈ 平板横屏一屏宽，1:1 显示不缩放） |
| 左栏目录 | **300px**，底 `#f3f7fc`、右边框 3px `#014198`；**只在讲义最开头出现一次**，之后为空白栏（手写留白） |
| 右栏正文 | 1300px 区域（内边距 30px → 有效 1240px），正文容器 `zoom: 1.6`，故正文排布宽度 ≈ **775px**（≈ A4 正文宽） |
| 目录层级 | **两级**：`h2`（章／附录）＋ `h3`（节）；进入附录后不再收 `h3` |
| 分页 | **无**。删除源文件的 `@page{size:A4;…}`，全篇连续流式 |
| 文内目录 | **移除**（已搬到左栏）；同时移除「本文件为 OneNote 导入优化版…」说明行 |
| 封面标签 | 末行 `OneNote 适配版` → `屏幕连续版` |

> 正文内容与 OneNote 版**逐字一致**，改的只有版式与目录位置。

---

## 四、分片规范（这是「无切割感」的关键）

| 项 | 规定 |
|---|---|
| 切点 | **一律落在块与块之间**（正文顶层块 = 表格 / 段落 / 标题），**绝不切断表格或段落** |
| 单片上限 | **16000px**（避开 WebP 单边 16383px 上限与移动端解码上限；规划时再扣 150px 安全余量） |
| 命名 | `NN_<实际切高>px.png`，序号即导入顺序 |
| 单块超限 | 若**单个块本身**＞上限（如一张超长表格），该块单独成片、文件名加 `_超限`，并在日志告警供人工确认 |
| 与 PDF 对应 | PDF 一片一页，页数 = 图数 |

**实测数据（2026-10，本机 Playwright 1.60 + Chromium）**

| 讲义 | OneNote 版渲染高 | 屏幕版画布高 | 切片数 | 成图单张 |
|---|---|---|---|---|
| 中医内科学·心系病证 | 39,386px（1600 宽） | 82,503px | 6 片 | 0.9–3.2MB / 片 |
| 中医内科学·肺系病证 | 55,592px（1600 宽） | 114,874px | 8 片 | 1.3–2.9MB / 片 |

> A4 版式下同样内容要 50+ 页；本形态**一章只需 6–8 张**，且切点全在语义边界。

## 五、生成命令

```bash
python scripts/render_screen_lecture.py "<讲义>_OneNote版.html"
# 常用可选参数
python scripts/render_screen_lecture.py "<讲义>_OneNote版.html" \
    --out-dir "<目录>" --max-slice 16000 --dpr 1 --formats png,pdf
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--width` | 1600 | 画布总宽 |
| `--rail` | 300 | 左栏目录宽 |
| `--zoom` | 1.6 | 正文字号整体放大倍率（改小→画布变矮、字变小） |
| `--dpr` | 1 | 截图设备像素比；平板上想放大细看可设 2（体积/内存数倍增长，需先确认平板能解码） |
| `--max-slice` | 16000 | 单张长图最大高度 |
| `--formats` | png,pdf | 可只出 `png` 或只出 `pdf` |

**依赖**：`playwright`（Chromium）、`Pillow`。

## 六、实现陷阱（改脚本前必读）

1. **不要用「放大视口 + full_page」截图**。实测页面高到 8 万 px 时，Chromium 会漏画远离首屏的区域
   （后半段整片空白，且不报错）。本脚本改为**逐片渲染**：每片只 `display` 该片内的块，
   其余 `display:none`，于是每次 `full_page` 都 ≤ max-slice，稳稳在安全范围内。
2. **`clip` 无法超出视口**：`page.screenshot(clip=...)` 超出视口的部分会被截断（返回视口尺寸），
   不能用它取长图。
3. **WebP 单边上限 16383px**，整章长图用不了 WebP；文字类内容 **PNG 比 JPEG 更小也更清晰**
   （实测 7.4MB vs 11.3MB）。
4. **Pillow 默认拒绝 >1.79 亿像素**（`DecompressionBombError`），脚本已设 `Image.MAX_IMAGE_PIXELS = None`。
5. `zoom` 会**同时**放大字号与行高，故画布高度约为原稿的 1.6 倍——这是把 A4 排布放大到屏幕字号的正当代价。

---

## 七、硬性规则（质检会逐条查）

1. 屏幕版 HTML 内 `size:A4` 计数 = **0**（不得残留 A4 分页）。
2. 左栏目录条目数 = `h2 数 + 附录前的 h3 数`；文内不得再出现旧的目录表。
3. **每张成图高度 ≤ `--max-slice`**（`_超限` 命名的片除外，且必须人工确认）。
4. **无空片**：不允许出现整片单色（脚本会打 `空片，请检查！`）。
5. 切点不得落在块内部（`_超限` 片除外）。
6. 图数 = PDF 页数。
7. 正文内容与 OneNote 版逐字一致（唯一允许差异 = 移除的文内目录与说明行、封面末行标签）。

## 八、导入与批注操作（交付时一并告诉用户）

**华为笔记（HarmonyOS 5.x）**
1. 笔记 → 新建无界笔记（无界画布无固定纸张，内容可无限延伸）
2. 依次「插入图片」把 `<图/01_*.png、02_*.png…>` 按序放入，纵向排开
3. 直接在图上用笔写批注；左栏那条浅蓝空白栏就是预留给手写的

**StarNote**
1. 新建 → 导入文件（支持图片）；或先在无界笔记里插图片
2. 有「页面留白」可用于额外补白；「笔记大纲」可另建章节目录

> 交付时提醒：长图导入后**不要**让 App 自动压缩（会糊）；若平板解码吃力，
> 改用 `--max-slice 8000` 重出更小的片。
