# Guided Reader（通用版）

在原来的教材上读、问、注，把不懂的地方真正弄明白。

基于 408 Guided Reader 改造的通用教材阅读器：不绑定特定教材，任何 PDF 都可以导入阅读，配合批注、AI 问答（Skill）、目录跳转与 PDF 写回，构成一个本地优先的学习工作台。

## 原书还是原书

Reader 不会把教材改写成另一本"AI 教材"。PDF 始终是阅读主体；OCR、目录、AI 解释和批注，都贴在书的周围。AI 只是终于知道你在学什么。

## 功能

- **通用教材导入**：任意 PDF 可导入。有文字层的直接用原生文字；扫描件通过本机 Umi-OCR 识别（可选字、搜索、锚定批注）；含书签的 PDF 自动解析大纲，目录点击直达对应页。
- **书库管理**：卡片视图与五列表格视图（封面 / 教材名称 / PDF 页数 / 上次阅读 / 操作）一键切换，视图偏好本地记忆。封面直接取该 PDF 的首页渲染图，不用另配图片；标题栏的 **PDF 文件夹** 按钮可跳到教材在本机的实际存放位置。
- **六类批注**：高亮、下划线（文字锚定，换版本可重锚）、文本框、区域高亮、批注便签（彩色折角贴在页边，双击输入，写回 PDF 时是标准便签注解）、AI 问答批注（把提问与回答一键固化到原文位置）。文本框与便签可拖动边角自由调整大小。全部支持增改删与跨会话保留。`Ctrl+Z` 可依次撤销本次会话内新建的批注——高亮、下划线、笔记、文本框、区域高亮、便签一视同仁。
- **批注写回 PDF**：三种模式可配（关闭 / 手动导出 / 自动写回）。自动写回直接把批注同步进 PDF 文件本体（默认写源文件，写前自动备份），批注跟着文件走——云盘同步、分享给别人都能看到。写回的是标准 PDF 注解（`/Highlight`、`/Underline`、`/FreeText`、`/Square`、便签 `/Text`），任何阅读器都能识别；AI 笔记还会内嵌一个紫色 "AI" 徽标外观流，在外部阅读器里也能一眼认出哪条是 AI 生成的。Reader 自身不重复绘制这些原生注解，回注后不会出现两条线。
- **AI 问答与 Skill**：选中原文即可提问，回答里的术语可继续追问；首轮提问时可在原文摘录下方补充自己的问题，AI 会同时回应原文与你追问的点（留空则只解释所选文字）。提问时可选择技能（Skill）——默认内置 `yixue-zonghe` 医学综合技能，也可以从本地目录安装自己的技能包（SKILL.md + references）。知识决定回答风格，模型决定由谁回答，两者独立配置。
- **AI 对话留痕**：每次问答（首轮、追问、深入一层）完成后自动归档到本地数据库，AI 面板顶部的「历史」可随时回看完整问答、导出 Markdown 或删除；关掉 Reader、换一本书都不会丢，避免为同一个问题重复消耗 token。历史为只读回看，想继续追问仍需重新发起。
- **国内模型全家桶**：DeepSeek、智谱 GLM、通义千问、Kimi、豆包（火山方舟）、MiniMax、讯飞星火、腾讯混元、硅基流动，以及自定义 OpenAI 兼容接口。API Key 走 Windows 凭据管理器或环境变量，不进仓库。
- **Markdown 导出**：Assistant 问答、Master 话题、保存的解释、批注汇总，均可导出为带来源页码与原文选段的本地 .md 文件。
- **Markdown 笔记本**：平台侧栏「笔记」以独立小窗打开，可与 Reader 并排陪读。支持 Markdown 编辑与实时预览（含公式）、自动保存（停笔 1.5 秒 / `Ctrl+S`）、按「置顶 / 今天 / 昨天 / 本周 / 更早」分组的历史列表、关键词搜索、可选关联教材与页码（删教材不丢笔记），以及单条 / 全部导出 .md。笔记只存本机数据库，不经任何外部服务。
- **Master 学习对话与 Learning Memory**：按知识点保留长期学习对话，收纳值得回看的内容。

## 快捷键

| 快捷键 | 作用 |
| --- | --- |
| `Ctrl+Z` | 撤销本次会话内刚创建的批注（高亮 / 下划线 / 笔记 / 文本框 / 区域高亮），连续按可逐条回退，不影响已有批注 |
| `Ctrl+S` | 立即把当前批注写回 PDF，不等自动写回的定时触发 |

高亮、下划线、笔记、问 AI、文本框、区域高亮、便签模式、全书批注面板等操作的按键，可在 Reader 设置页自行录制替换（持久化到数据目录 `shortcuts.json`）。

## Windows 安装版

普通用户不需要装 Python 或任何运行库。安装包由外层 SW_Guided_Reader 壳（Tauri）打包发布，Reader 作为内置后端随附：

- **完全自包含**：内置 Python 运行时、离线 WebView2、技能包，断网或纯净系统也能直接装。
- **默认安装到 `D:\LearningTools`**：安装向导里可改；D 盘不可用或当前用户无写权限时自动回退到系统默认位置；升级时优先沿用上次的安装路径。
- **数据独立存放**：教材、笔记、批注、学习记录都在 `<安装目录>\Reader`，升级与卸载都不会删除。
- **更新**：新版只发布一个 `SW_Guided_Reader-<版本>-安装包.exe`，直接双击运行、选择"重新安装"即可原地覆盖升级（`/UPDATE /S` 可静默升级），教材、笔记与学习记录都在 `Reader` 里，不受影响。安装向导改为默认装到 `D:\LearningTools`，升级时沿用上次的安装路径。
- **卸载**：设置 → 应用 → 已安装的应用，或运行安装目录下的 `uninstall.exe`；程序文件清理干净，`Reader` 数据目录保留。

## 从源码运行（Windows）

需要 Python 3.11+、Node.js 20+（仅首次安装依赖时需要），以及 Chrome 或 Edge。

首次安装：

```
python -m pip install -e . -i https://pypi.org/simple
npm ci
```

之后双击 `start.bat` 即可——它会启动本地服务并打印访问地址（带一次性 token），把 `READY http://127.0.0.1:8765/?token=...` 复制到 Chrome/Edge 打开。保持终端窗口开启。

手动启动（可自定义数据目录）：

```
python -m reader_service --data-dir <你的数据目录>
```

数据目录默认在 `%LOCALAPPDATA%\GuidedReader`，存放数据库、导入的 PDF、技能包与导出文件。

打包独立后端（PyInstaller onedir，供桌面壳内嵌使用）：

```
python -m PyInstaller sidecar/reader-service.spec --noconfirm
```

产物在 `dist/reader-service/`，需要连同 `_internal/` 整个目录一起分发。

## 配置

模型与 OCR 通过环境变量或数据目录 `config.json` 配置，完整项见 `.env.example`：

- `GUIDED_READER_{PROVIDER}_API_KEY`：各模型服务商的 Key（provider 取小写名，如 `GUIDED_READER_DEEPSEEK_API_KEY`）
- `GUIDED_READER_UMI_OCR_ENDPOINT`：Umi-OCR HTTP 服务地址（默认 `http://127.0.0.1:1224`），`GUIDED_READER_UMI_OCR_DISABLED=1` 彻底禁用
- `GUIDED_READER_DEFAULT_SKILL_DIR`：默认安装的技能包目录（指向**含 SKILL.md 的文件夹**；如果技能包多套了一层 `SKILL/`，指向那一层）
- 批注写回开关也可在 Reader 设置页中直接调整

OCR 依赖本机安装 [Umi-OCR](https://github.com/hiroi-sora/Umi-OCR)（免费、离线、解压即用），在它的全局设置里允许 HTTP 服务即可。Umi-OCR 未启动时扫描件选字/搜索不可用，但不影响任何其他功能。

### API Key 存放与发布约束

- **发布物不含任何 Key**：安装包是空配置，开箱没有任何模型凭据；使用者在设置页填入自己的 Key 即可。
- **Key 只存在本机**：优先写入 Windows 凭据管理器（条目名 `408-guided-reader-<provider>`），其次读取本机环境变量。数据目录的 `config.json` 只保存批注写回等偏好，不写 Key。
- **打包前强制体检**：`发布安装版.ps1` 在构建前扫描 `src/`、`sidecar/` 与被打包的资源目录，命中 `sk-…`、`AIza…`、智谱 `id.secret` 这类真实 Key 形态会直接中止打包并列出文件名与行号。测试脚本里的 `mock-*`、`test-loopback-key` 等占位值不会触发。

## 排障

- **后端启动失败 / 页面显示"未发送任何数据"**：先看数据目录下的 `reader-service.log`，里面按 `[out]` / `[err]` 记录了后端的标准输出与错误（超过 4MB 自动重置）。启动失败时界面提示里也会给出这个路径和后端最后几行输出。
- **服务地址**：后端就绪后会把带 token 的地址写入 `<数据目录>\reader-launch.json`，可用它确认端口与进程号。
- **有残留进程占端口**：结束 `reader-service.exe` 后重新打开 Reader；桌面壳会在主程序退出时一并回收后端，正常退出不需要手动清理。

## 与桌面外壳的集成

Reader 后端启动后会把带 token 的访问地址写入数据目录的 `reader-launch.json`；桌面安装版由 Tauri 外壳（Reader.exe）以侧进程方式拉起本后端，读到 READY 地址后由 WebView2 直接加载其页面。独立开发时可用 `python -m reader_service --port <端口> --data-dir <数据目录>` 单独运行。

## 当前状态

面向 Windows 本地单用户。习题功能已移除；导读/行间教学（teaching）与知识点自动构建保留原有能力，对任意教材为可选增强。AI 与 OCR 不可用时，原 PDF 始终可以正常阅读。
